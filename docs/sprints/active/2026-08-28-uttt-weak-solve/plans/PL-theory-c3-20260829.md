### Normative check order and reason codes (verify.c3; the battery's expectations depend on this order — do not reorder without updating both)

Fault/reason enum (one CLI-visible code per row; C3 `faultdef` per code or one fault + code field — implementer's idiom choice, but the REPORTED code strings below are fixed):

Certificate, header stage, in order:
`E_MAGIC` → `E_SCHEMA_VERSION` → `E_CLAIM_TAG` → `E_HEADER_RESERVED` → `E_RULESET` (unknown id or digest mismatch) → `E_SYMMETRY` → `E_ROOT_STATE` (ill-formed or non-canonical root field) → `E_RULE_IDS_V0` (rule_count ≠ 0) → `E_MANIFEST_EMPTY` → per-row `E_ROW_FLAGS` → `E_ROW_PLY_RANGE` (ply > 80) → `E_ROW_ORDER` (ply not strictly descending / ordinal gaps) → `E_CHUNK_LAYOUT` (first offset ≠ header-region end, gaps/overlaps, file end ≠ last chunk end — trailing bytes land here) → `E_MANIFEST_DIGEST`.
Note `E_TRAILING` is an alias-free case of `E_CHUNK_LAYOUT`; report `E_CHUNK_LAYOUT`.

Certificate, streaming stage, chunks in manifest order:
per chunk `E_CHUNK_DIGEST` (recompute over byte_length at offset) → `E_CHUNK_COUNTS` (record_count ≠ fixed_count + rule_count, or chunk bytes ≠ declared records) → `E_RULE_RECORD_V0` (rule_count > 0 in a v0 stream);
per fixed record, in order: `E_RECORD_RESERVED` (byte 39 ≠ 0) → `E_PAYLOAD` (non-PROVER payload ≠ 0xFF) → `E_KIND_TAG` (kind ∉ {0,1,2} in fixed section) → `E_ILLFORMED_STATE` (mask overlap / high bits / parity) → `E_FORCED_CLOSED` (forced ≤ 8 at a closed board) → `E_NONCANONICAL` (state ≠ its own canonicalization) → `E_DUP_STATE` → `E_PLY_MISMATCH` (mark count ≠ chunk ply) → `E_KIND_TERMINALITY` (terminal state not TERMINAL, or TERMINAL state not terminal) → `E_KIND_SIDE` (PROVER/OPPONENT kind inconsistent with prover-vs-side parity) → node rule: `E_TERMINAL_CLAIM` (terminal fails the claim) / `E_ILLEGAL_MOVE` (PROVER move illegal) / `E_CHILD_MISSING` (PROVER child unverified) / `E_REPLY_MISSING` (any OPPONENT legal reply's child unverified).

Certificate, end stage: `E_TOTALS` (streamed per-kind counts ≠ header totals) → `E_ROOT_ABSENT` (header root not in verified set).

Verdict manifest (§7 steps): `EV_PARSE` (magic/version/value tag/reserved/trailing) → `EV_MEMBER_TAG` (unknown member claim tag; part of step 1) → `EV_MEMBER_PATH` (§4.5 path rules) → `EV_MEMBER_ABSENT` (target missing/unreadable) → member certificate verified fully (its own E_* code surfaces on failure) → `EV_MEMBER_DIGEST` → `EV_CLAIM_BINDING` (member.claim ≠ certificate header claim) → `EV_FIELD_MISMATCH` (schema/ruleset/symmetry/root) → `EV_COMPLETENESS` (exact multiset per game value) → deliverable mode only: `EV_ROOT_NOT_INITIAL`.
