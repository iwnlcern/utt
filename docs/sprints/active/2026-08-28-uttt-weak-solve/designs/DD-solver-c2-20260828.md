## 0. Shape and non-goals

The solver is a local-first, layered proof engine for weakly solving the rule-lock game, built to run end to end on the development laptop and to scale by moving the same binary and artifacts to a bigger box (operator direction, grill).
Non-goals: certificate byte format beyond the seam in §9 (theory-owned and already locked; this design consumes, never redefines it); strategy-rule leaf closure (ROADMAP gate 2; v1 emits no RULE nodes and closes leaves only on terminals); sharded/distributed search (deferred behind named triggers, §7); engine/ edits of any kind (A6).

## 2. State identity, adapter, and canonicalization (consumes theory §2 exactly)

**Identity** is the theory contract's 37-byte serialization (DD-theory-c2 §2.2), verbatim:
bytes 0..17 = `x[0..8]` as uint16 little-endian, bytes 18..35 = `o[0..8]`, byte 36 = `forced` (0..8, or 9 = ANY).
Side-to-move is derived from mark parity (X to move when popcounts are equal) per R-s2-1; TieState and budgets are excluded from identity.
There is no hash-as-identity anywhere; hashes are integrity/lookup surfaces only.

**Adapter.** `SolverState` wraps `engine::Position` for movegen/apply/terminal.
Construction from a 37-byte identity goes through `Position::from_parts` with the derived compatibility TieState — `from_parts` requires one and rejects `NullFirstMove` after any mark (engine/src/core/position.cpp:95-134) but does not enforce parity, so the adapter enforces, before calling it, the theory well-formedness rules (§2.6): mask bits 9..15 zero, disjoint masks, `0 ≤ popcount(x) − popcount(o) ≤ 1`, forced open.
Compatibility TieState: empty board → `NullFirstMove`; otherwise `TieState::X` when popcounts are equal (X to move), else `TieState::O`.
The adapter's only mutation API is `apply(state, move)` — the mover is derived from parity internally, so wrong-mover application is inexpressible; `engine::Position::applied(mv, Seat)` is never exposed.

**Canonicalization** implements SYMMETRY_ID `d4-lexmin-v1` (theory §2.3–2.4) exactly: the eight destination tables `e, r90, r180, r270, mh, mv, md, ma` as printed in theory §2.3, applied simultaneously to macro and local grids, `forced ≤ 8 → g(forced)`, ANY fixed; `canon(s)` = lexicographically smallest of the eight 37-byte serializations compared as unsigned bytes.
Implementation: precomputed `board_perm[8][9]` and `mask_map[8][512]` tables generated from the theory tables, with a generator-time cross-check against a direct cell-by-cell implementation of theory §2.3.
Color-swap is not part of identity (theory §2.3, grill decision); if the solver ever exploits it privately in RAM tables (revisit trigger: a dedicated probe demonstrating ≥1.5× effective TT hit-rate gain), certificate-facing and ProvenStore state remains color-unswapped.
Canonicalization applies at store boundaries (TT probe/store, ProvenStore records, certificate seam); search walks raw positions and maps moves through the minimizing transform's inverse permutation when crossing a store boundary; **no transform ever serializes** — stored moves are cell indices 0..80 in the canonical frame of the state they attach to (theory §2.5).

**Hashing.** TT keys are XXH3-64(seed 0) of the 37 canonical bytes; the s1 Zobrist (orientation-bound, tie-coupled) is not reused.
The working TT is lossy and tag-checked; every ProvenStore record carries the full 37-byte identity.
Traceability: MR-1; theory §2; R-s2-1; measured D4 saturation ×8 by ply 7 (planner c1 §3).

## 3. Claims, outcome machine, and kernels

**Claims** are the theory contract's four (§3.1): `WIN_X`, `WIN_O`, `NOLOSS_X`, `NOLOSS_O`.
The game is finite, perfect-information, and determined, so two complement identities hold at every state `s`:
`WIN_X(s)` false ⟺ `NOLOSS_O(s)` true, and `NOLOSS_X(s)` false ⟺ `WIN_O(s)` true.
Two monotone implications also hold: `WIN_X(s) ⟹ NOLOSS_X(s)` and `WIN_O(s) ⟹ NOLOSS_O(s)`.
These four are the only cross-claim inferences the solver may use, and disproofs are always normalized through the complement identities into proofs of the complementary claim before storage — the ProvenStore holds proven claims only.

**Outcome state machine** (locked; verdicts close only through completed claim proofs assembled by theory's verdict manifest, §7 there):

- `WIN_X` proven at the root → WIN_X certificate → X-win verdict.
- `WIN_X` disproven at the root → that disproof is a NOLOSS_O proof → NOLOSS_O certificate; the verdict is still open.
- `NOLOSS_X` proven at the root → NOLOSS_X certificate; draw verdict only once the NOLOSS_O certificate also exists.
- `NOLOSS_X` disproven at the root → WIN_O proof → WIN_O certificate → O-win verdict.

Run sequencing (grill decision): attempt `WIN_X` first; on disproof, the normalized NOLOSS_O facts are banked and the run proceeds to `NOLOSS_X`.
**The objective switch is a scheduling heuristic with no completion semantics**: suspending `WIN_X` early leaves the WIN_X/NOLOSS_O obligation open in the manifest, and it must be resumed and completed (proven or disproven) before any verdict that depends on it closes.
Default switch heuristic, per kernel, with the switch-favoring direction explicit (PN = estimated leaf effort to prove the claim, DN = to disprove it, per the standard df-pn convention):
kernel A — proof-hardness ratio: fire when `PN(root) ≥ saturating_mul(10, DN(root))` in unsigned 64-bit saturating arithmetic (proof effort dwarfing disproof effort favors suspending the proof attempt); the ∞/0 boundary cases never reach the heuristic — `PN(root) = ∞` or `DN(root) = 0` means the claim is disproven and `DN(root) = ∞` or `PN(root) = 0` means it is proven, both handled by the §3 outcome machine, and saturated finite values compare like any other;
kernel B — refuted-root-children fraction `≥ 0.8` (numerator: root children proven not-winnable for X; denominator: all root children; larger favors switching);
either signal must hold at two consecutive checkpoint reviews to fire.
Both constants are nonbinding tunables calibrated at the first checkpoint with real disproof data — the operator may retune them at any time, and no verdict ever depends on them.
"No work discarded" means exactly: ProvenStore facts are keyed by (canonical state, claim) and survive the switch; facts transfer across objectives only through the four inferences above; working-TT heuristics do not transfer.

**`ProofKernel` interface**: `solve(claim, root, canonicalizer, working_tt, proven_store, limits) → proven | disproven | out_of_resources`, two implementations:

- Kernel A — df-pn with ε-widening and TT-resident proof/disproof thresholds.
  PN numbers are heuristics only, evictable, never exactness claims; DAG double-counting costs efficiency, never soundness (A4); mitigation is current-path relative bounds, no heavier GHI machinery.
- Kernel B — exact-WDL negamax: null-window boolean DFS, first-winning-child cutoff, iterative widening by ply budget; deterministic, trivially extractable.

Exactness in both kernels bottoms out only at terminals (v1: no RULE leaves).
Traceability: MR-2; theory §3; A4; A5; grill Q4.

## 4. The A-vs-B spike (pre-registered decision procedure)

**Probe set** (fixed before any run, recorded in a spike manifest):
positions sampled at plies 14, 16, and 18, each solved **to terminal** for the claim `WIN_mover ∨` its complement (a full boolean resolution), so every decision observation is an exact proof or disproof — no horizon values enter the statistic.
Sampling procedure: seeded SplitMix64 PRNG (seed recorded in the spike manifest); random legal playout from the root to the target ply; reject terminal states and canonical duplicates of already-selected probes; accept the first 4 per ply tier (12 probes total).
A predeclared easier tier at plies 16, 18, 20 (same procedure, fresh seed recorded up front) is the only permitted fallback if the primary tier cannot complete inside the timebox; a fallback may never turn horizon values into proofs or rewrite the comparison after observing results.

**Run protocol**: each (kernel, probe) run starts from a fresh, empty, byte-identical store snapshot — no fact sharing between kernels or between probes; single-threaded, one repetition (deterministic); alternating run order A,B per probe; per-probe timeout 2 hours; cold caches not controlled beyond process restart per run (recorded).

**Metrics**: wall time-to-proof, proven facts written, nodes expanded, peak RSS — per completed probe.

**Decision rule** (written here, before the spike): over probe pairs where **both** kernels completed, compute the median of time_B / time_A; kernel A becomes primary iff that median ≥ 2.0; otherwise kernel B is primary.
Pairs with either side timing out are excluded from the statistic and reported separately.
Coverage floor: the decision needs ≥ 8 completed pairs; below that, fall to the easier tier; if the easier tier also yields < 8, the predeclared no-decision default is kernel B primary.
The losing kernel is retained behind the interface as cross-check oracle.
Timebox (grill decision): ~3 days of laptop probe runs governs how far the tiers get, never the rule.
Traceability: MR-3; dispatch acceptance criterion 1; grill Q1.

## 5. Storage

**Working TT** (lossy, RAM, never persisted): fixed-size power-of-two table, 4-way buckets, 16-byte entries, plus a parallel full-identity sidecar array (37-byte canonical identity per way, engine `TT::Mode::FullKey` pattern, tt.hpp:63-112).

**Entry encoding `tte-v1`** (complete, 128 bits; round-trip and boundary tests in §10):

```text
word 0 (64 bits): tag 56 | generation 8
word 1 (64 bits): kind 2 | claim 2 | move 7 | pn 24 | dn 24 | reserved 5 (MUST be 0)
  kind  : 0 = empty, 1 = A-heuristic (pn/dn live), 2 = B-exact-bound (move lives,
          pn/dn MUST be 0), 3 = reserved (refuses)
  claim : the entry's claim (0..3, §3 numbering)
  move  : 0..80 best/witness move in the canonical frame; 127 = none; 81..126 refuse
  pn,dn : 24-bit saturating projections — 0 encodes 0; 1..16777213 literal;
          16777214 = finite-saturated ("at least this much", compares as its value);
          16777215 = ∞ (proven/disproven side)
```

The §3 switch heuristic never reads these projections: root PN/DN for the switch signal come from kernel A's in-memory root node, which df-pn keeps at full u64 width in its recursion; TT projections are ordering/threshold hints only, made lossy-safe by the collision rule below (nothing exact rides an A-heuristic entry).

**Kind-2 result semantics (locked)**: every kind-2 entry stores a **proven normalized claim** — the `claim` field names the claim that is TRUE at the sidecar state (disproofs are normalized through the §3 complement identities before storage, exactly as in the ProvenStore; polarity therefore needs no extra bit).
A sidecar-matched kind-2 hit answers a query for claim Q from stored claim C by the §3 inference lattice, exhaustively:
C = WIN_X decides all four queries (WIN_X, NOLOSS_X proven; WIN_O, NOLOSS_O disproven); C = WIN_O symmetrically; C = NOLOSS_X answers Q = NOLOSS_X proven and Q = WIN_O disproven and is a **miss** for Q ∈ {WIN_X, NOLOSS_O}; C = NOLOSS_O symmetrically.
An entry holds one claim; a state with two proven no-loss claims surfaces whichever replacement kept, and the other query path misses to the ProvenStore or re-search — a miss is always sound.
Witness validity is independent of any query's polarity: `move` is meaningful iff the *stored* claim's prover is to move at the sidecar state and the state is nonterminal; otherwise `move` MUST be 127 (none).
Kernel B's exact bounds ride kind-2 entries and are exact only together with sidecar identity per the collision rule.
**Collision-safety rule (locked)**: a TT hit may establish anything exact — a proof, disproof, exact bound, boolean cutoff, kernel return, or ProvenStore append — only when the sidecar's full 37-byte identity equals the probing state's canonical identity; a tag-only match without sidecar equality is a miss for exact purposes and may at most inform move ordering or PN threshold scheduling.
A 56-bit tag can collide across distinct canonical states, so this rule is soundness-bearing, not an optimization note; false misses only re-search.
Required tests (§10): forced same-tag/different-state probes for both kernels proving result equivalence to an empty-TT search and proving no false durable fact is emitted.
**Publication protocol (locked)**: the entry and its sidecar are one unit under a striped mutex (256 stripes over bucket index), taken by every reader and every writer in every mode — even where the 16-byte entry itself would be lock-free — because no entry-ordering trick makes the pair safe: under entry-last publication, a same-tag replacement of state A by state B can expose sidecar B beside stale payload A, and the full-identity check would then bless A's payload as B's exact result.
Locked reads make mixed-generation observation structurally impossible; the 16-byte entry layout is retained purely as the wire format so a future lock-free protocol (seqlock/versioned pair) can arrive as its own reviewed amendment if c4 contention measurements demand it.
c3 is single-threaded and pays nothing; c4 measures stripe contention before any such amendment.
Default 8–16 GB on the laptop, flag-sized, counting both the entry table and the sidecar (~56 B per way combined).
The s1 TT's 32-byte double-interval entry is auction-shaped; its bucket + FullKey-sidecar pattern is exactly what carries over (implementer c1 §6).

**Two result classes**, named precisely (fixes the rev-1 contradiction):
*ephemeral exact results* — proofs whose subtree cost < K expanded nodes (K default 10³, flag-tunable; grill Q3): correct but deliberately unlogged, TT-resident at most, recomputed on demand (extraction, resume);
*durable proven facts* — proofs with cost ≥ K: written to the ProvenStore.
**Root exemption**: the fact that resolves a run's root claim (proof or normalized disproof at the certificate root) is logged unconditionally, bypassing K — K is tunable and every proof cost is finite, so no threshold choice may leave a closed root claim without its durable record; §6's cross-field gate refuses any checkpoint that tries.
Soundness never rests on either store: every fact is re-derivable, and the certificate checker re-verifies everything; the ProvenStore is the durable record of hard work, not an oracle.

**ProvenStore record** (48 bytes, all integers little-endian, format version `psr-v1`):

```text
bytes  0..36 : canonical state identity (theory §2.2, 37 bytes)
byte     37  : claim (0=WIN_X, 1=WIN_O, 2=NOLOSS_X, 3=NOLOSS_O)
byte     38  : witness move (0..80 in the canonical frame of bytes 0..36;
               0xFF = none, mandatory for opponent-to-move and terminal states)
byte     39  : flags (reserved, MUST be 0 in psr-v1; nonzero rejects)
bytes 40..47 : XXH3-64(seed = 0x7073722D7631 "psr-v1") of bytes 0..39
```

Records store proven claims only (§3 normalization).
Duplicate handling is totally ordered and deterministic: compaction sorts by the full record bytes `(state, claim, witness)` ascending; for each (state, claim) key the record with the smallest witness byte is the named winner and exactly one record survives — two legal input orders therefore compact to identical output bytes.
Claim-consistency check, closed over the inference lattice: a state's surviving claim set must be a subset of one of the three truth-assignment sets `{WIN_X, NOLOSS_X}`, `{NOLOSS_X, NOLOSS_O}`, `{WIN_O, NOLOSS_O}`; any other combination — including the complement pairs and the closure-implied impossibles such as `{WIN_X, WIN_O}` — is a fatal integrity error: compaction refuses with `E-PSR-CONTRADICTION` and the run halts for investigation.

**Durability and visibility**: appends batch in a 4 MiB buffer; a batch commits via `write` + `fdatasync`.
A durable fact is *search-visible* immediately after the in-process append (a crash merely recomputes it) but *checkpoint- and extraction-visible* only after its batch's `fdatasync` returns — extraction and epoch accounting never read past the last durable offset.
Log integrity has one rule, used consistently by the manifest pin, publication, recovery, and tests: the manifest's per-segment `digest_xxh128` covers exactly bytes `[0, durable_bytes)`; on resume that range must verify, and bytes beyond `durable_bytes` (appends after the manifest was written, lost from no manifest but present on disk) are salvaged per-record — validated by the psr-v1 record checksum in order, truncating at the first invalid or partial record (the torn tail).

**Compaction** (c3 execution model: foreground, at epoch boundaries, single-threaded; c4 may move it to a dedicated worker): external-sort log segments by full record bytes — ply = popcount of the state, derived, not stored, selects the target file — into immutable per-ply layer files `layer-<ply>-<epoch>.psl`, each with its XXH3-128(seed 0) whole-file digest recorded in the manifest.

**Layer file format `psl-v1`** (fail-closed parsing; the manifest's layer-format version names this section):

```text
bytes  0..5  : magic "PSLv1\0"
bytes  6..7  : format version, uint16 LE (= 1)
bytes  8..9  : ply, uint16 LE (0..81; 0 is the root's layer)
bytes 10..15 : reserved, MUST be 0
bytes 16..23 : record_count, uint64 LE
bytes 24..   : exactly record_count psr-v1 records (48 B each), strictly
               ascending by full record bytes, one per (state, claim) key
```

A reader refuses on: wrong magic or version; nonzero reserved bytes; file size ≠ 24 + 48 × record_count; any record whose per-record checksum fails or whose state popcount ≠ ply; order violation or duplicate (state, claim); manifest whole-file digest mismatch.
Publication is atomic: write temp file → `fdatasync` file → `rename` → `fsync` directory; superseded log segments and prior layers are retained until the successor manifest **and** its `CURRENT` pointer (§6) are durable, then GC'd per §6's newest-two-generations rule.
Probe path on TT miss: binary search in the mmap'd layer of the state's ply.
Traceability: MR-4; grill Q1/Q3; measured 55–140 B/entry and the ~ply-10–12 wall (A3).

## 6. Checkpoint and resume

A checkpoint is a manifest plus the store files it names.
Manifests are **immutable and versioned** — `manifest-<epoch>.psm`, written once via temp + `fdatasync` + `rename` + directory `fsync`, never overwritten — and a separate `CURRENT` pointer file selects the newest one (publication and recovery below); a single mutable manifest path was rejected because `rename` unlinks the previous generation, which would make "previous manifest remains authoritative" unsatisfiable after a refused successor.
The manifest pins, and resume refuses on any mismatch:

- record-format version (`psr-v1`) and layer-format version (`psl-v1`, §5);
- rules dependency identity: XXH3-128 over the concatenated bytes of the exact engine-core source list (`position.{hpp,cpp}`, `local_table.{hpp,cpp}`, `types.hpp`, `zobrist.{hpp,cpp}`) plus the solver adapter/canonicalizer sources;
- build identity: compiler id and version, flags, build type, and the solver executable's build id;
- canonicalizer: SYMMETRY_ID `d4-lexmin-v1` plus the generated-table digest;
- theory contract identity: DD-theory-c2-20260828 sha256 `629801c4b1cfc69f66390c47b72296d93867e46ac22ea142e9bfd2bdc8f41f0c`; RULESET_ID `uttt-s2-r1` and RULESET_DIGEST;
- root state (37 bytes, hex) and the claim set with per-claim status (`open | proven | disproven-normalized`, with the normalized target named);
- epoch counter, per-layer/per-segment file list with digests, last durable log offset.

**Manifest schema `psm-v1`** (strict, literal, complete — resume-state semantics):

```text
{
  "manifest_format": "psm-v1",          // string; MUST be first key checked; unknown value
                                        // refuses before any other key is interpreted
  "epoch": <uint, 0..4294967295>,       // equals the <epoch> in this file's own name
  "complete": <bool>,                   // durable epoch-completion flag
  "record_format": "psr-v1",            // string enum, exactly this value
  "layer_format": "psl-v1",             // string enum, exactly this value
  "rules_digest": <hex32>,              // XXH3-128 of the pinned engine+adapter source list
  "build": {                            // object, exactly these five string keys
    "compiler_id": <string>, "compiler_version": <string>,
    "flags": <string>, "build_type": <string>, "executable_build_id": <string>
  },
  "canonicalizer": {                    // object, exactly these two keys
    "symmetry_id": "d4-lexmin-v1", "table_digest": <hex32>
  },
  "theory_contract": {                  // object, exactly these three keys
    "design_doc_sha256": <hex64>, "ruleset_id": "uttt-s2-r1", "ruleset_digest": <hex32>
  },
  "root_state_hex": <hex74>,            // the 37-byte root identity
  "claims": [                           // array of EXACTLY 4 objects in this fixed order:
                                        // WIN_X, WIN_O, NOLOSS_X, NOLOSS_O
    { "claim": <claim-enum>, "status": "open" | "proven" | "disproven-normalized",
      "normalized_to": <claim-enum> | null }
    // cross-field: normalized_to is non-null iff status = disproven-normalized,
    // and must equal the complement (WIN_X→NOLOSS_O, NOLOSS_X→WIN_O,
    // WIN_O→NOLOSS_X, NOLOSS_O→WIN_X)
    // cross-field durability gate: for every entry with status ≠ "open", the
    // manifest's named layer/log set MUST contain the matching durable root
    // record — (root_state_hex's state, the proven claim: the entry's claim if
    // proven, its normalized_to if disproven-normalized) — guaranteed writable
    // by the §5 root exemption; resume validates the record's presence and
    // refuses the manifest otherwise; sub-K non-root results never close a
    // checkpoint claim status
  ],
  "layers": [                           // array, ascending ply, AT MOST one entry per ply
    { "file": <fname>, "ply": <uint, 0..81>,
      "record_count": <uint, 0..2^48>, "digest_xxh128": <hex32> }
    // ply 0 is valid and is exactly the initial root's layer (popcount 0); root
    // facts are durable by the §5 root exemption (unconditional logging), never
    // by any cost assumption, and use the ordinary per-ply path at their ply
  ],
  "log_segments": [                     // array, append order
    { "file": <fname>, "durable_bytes": <uint, 0..2^53−1>, "digest_xxh128": <hex32> }
    // cross-field: durable_bytes ≡ 0 (mod 48) and ≤ the file's size at open;
    // digest_xxh128 covers exactly bytes [0, durable_bytes) of the segment
  ]
}
```

Scalar grammars: `<hex32>`/`<hex64>`/`<hex74>` are lowercase hex strings of exactly that length; `<fname>` matches `^[a-z0-9][a-z0-9.-]*$`, resolves inside the store directory (no path separators, no `..`, no absolute paths), and is unique across `layers` + `log_segments`; `<claim-enum>` ∈ {"WIN_X","WIN_O","NOLOSS_X","NOLOSS_O"}; all `<uint>` are JSON numbers, integral, within their stated inclusive ranges (every domain is below 2^53 by construction).
Parsing is fail-closed: unknown keys refuse (forward compatibility is a version bump, not silent tolerance); missing required keys refuse; wrong types, out-of-range numbers, cross-field violations, and trailing bytes after the closing brace refuse; on open, each layer's psl header must match its manifest row (ply, record_count) and its whole-file digest.
No canonical-byte claim is made for manifest JSON; integrity and selection ride the digest in `CURRENT`.

**Publication and recovery (`CURRENT` pointer, `psc-v1`)**: `CURRENT` is a one-line text file `psc-v1 <manifest-file-name> <xxh128-of-manifest-bytes>\n`, published via temp + `fdatasync` + `rename` + directory `fsync` only after `manifest-<epoch>.psm` and every file it names are durable.
Recovery selects, in order: the manifest named by a well-formed `CURRENT` whose digest matches and whose schema and named files validate; otherwise the highest-epoch `manifest-*.psm` that validates end to end (schema, digests, named files) — a corrupt or schema-refused newer manifest is skipped and the valid predecessor wins; otherwise (first checkpoint never completed, or nothing validates) the store is uninitialized and the run starts fresh — stated, not implied.
Retention/GC: the previous generation's manifest and every file it references are retained until the successor manifest **and** its `CURRENT` pointer are durable; GC then deletes only files unreferenced by the newest two valid manifests.

An epoch is complete exactly when the manifest recording it as complete is durable — that manifest is the durable epoch-completion record, and re-running a completed epoch against the same manifest is a no-op.
Resume: validate manifest → verify file digests → truncate torn log tail → mmap layers → start cold.
Kernel transient state (DFS stack, PN tree) is deliberately disposable and recomputed; recomputation loss is bounded by the work threshold K.
Traceability: MR-4; dispatch scope item 4; A3/R2 constraint.

## 7. Concurrency and the scale-up seam

c3 is single-threaded (grill Q5): deterministic bit-match oracles, crash tests, spike runs; compaction runs foreground at epoch boundaries (§5).
c4 adds worker threads over root-orbit/subtree jobs against the shared TT (16-byte entries per §5's synchronization contract) and per-thread ProvenStore log segments merged by compaction.
Scale-up = the same binary and artifacts on a bigger box; all formats are fixed-width little-endian with no pointers.
Sharding stays deferred behind named triggers: proven-store working set exceeding 0.5× box RAM with degrading TT hit rate, or projected time-to-proof over ~6 weeks on the largest available single box.
Cloud provider deliberately unpinned; the plan picks a vendor when a deep run is commissioned (operator: local-first).
Traceability: dispatch scope item 8; grill Q5; brainstorm Q3.

## 8. Census (obligation O5) — solver-census-v1

`solver/tools/census`: BFS by ply with disk-backed external dedupe (sort-merge over 37-byte identities, sharing the compaction machinery).
Output: one CSV file, schema id + version in a `# solver-census-v1` header comment along with the manifest pins (rules identity, SYMMETRY_ID, build identity, PRNG-free — the census is deterministic) and the ply range; one row per ply, ascending, no gaps; **all counts are decimal ASCII integers of unbounded width** (no floats, no JSON — path counts exceed 2^53 in deep layers); ratios are the consumer's derivation, never emitted.
Columns, with exact definitions (`ply` = total mark count; the DAG is leveled, so every state's ply is intrinsic):

```text
ply             : layer index, 1-based
paths_alive     : legal move sequences of length exactly ply from the root
                  whose end state is nonterminal
paths_terminal  : legal move sequences reaching a terminal state at exactly ply
states_alive    : distinct 37-byte identities, nonterminal, at ply
states_term_wx  : distinct terminal identities at ply, kind MacroWinX
states_term_wo  : distinct terminal identities at ply, kind MacroWinO
states_term_dr  : distinct terminal identities at ply, kind AllClosed
canon_alive     : D4-canonical classes of states_alive
canon_terminal  : D4-canonical classes of the three terminal sets combined
transposed_alive: paths_alive − states_alive  (path-vs-state transposition mass)
cum_states      : cumulative states_alive + all terminal states, plies 1..ply
cum_canon       : cumulative canon_alive + canon_terminal, plies 1..ply
```

## 10. Testing and oracles

Oracle gates, split by what each source can actually assert (MR-6):

1. **Rules bit-match** — adapter legal moves, apply, terminal kind, and derived parity equal `engine::Position` behavior on exhaustively enumerated shallow states and on all alternating-relevant theory fixtures v1 rows (R-s2-3/R-s2-4).
2. **Exact-WDL oracle** — solver results equal AltSolver **only where AltSolver returns `complete && Quality::Exact`**; the corpus solves with `max_depth = remaining empties` so every leaf is terminal-resolved (AltSolver at a nonterminal horizon returns `Quality::Estimate`, engine/src/root/alt_solver.hpp:132-166, and propagates it upward — estimates are never comparison targets).
   Invariant + test: nothing of quality Estimate can reach the ProvenStore or extraction — kernels only emit terminal-grounded proofs, and a test asserts the store API has no estimate-shaped input.
3. **Cross-kernel agreement** — A and B agree on every **completed exact** probe pair; incomplete/out-of-resource pairs are reported separately and assert nothing.
4. **Census self-check** — §8 anchors.

Plus: crash-injection tests on the log and on compaction publication (kill mid-batch, mid-compaction, mid-manifest-replace; resume; verify no durable fact lost, no fact fabricated, superseded files intact until successor manifest durable); canonicalizer property tests (the eight theory §2.3 tables: legality/value preservation, canon∘canon = canon, move round-trip, generator cross-check); work-threshold boundary tests (K±1 behavior); format tests — psr-v1 (checksum rejection, reserved-flag rejection), psl-v1 (magic/version/reserved/size/order/duplicate/digest refusals), psm-v1 (unknown-version/unknown-key/missing-key/wrong-type/trailing-bytes/path-confinement/range/cross-field refusals), psc-v1 pointer refusals, tte-v1 encoding round-trip and boundary tests (0, literal max, finite-saturated, ∞, move sentinel/refusal band, reserved-bit and kind-3 refusals), ply-0 root-layer compaction/probe/resume/extraction test, segment-digest tests (digest over [0, durable_bytes) verifies; post-durable appends salvage per-record; torn tail truncates), **kind-2 polarity tests** — true and false results at prover-to-move, opponent-to-move, and terminal states, each query answered via the stored-normalized-claim derivation table and matching an empty-TT search, plus witness-validity checks independent of query polarity, **root-status durability tests** — terminal/easy-root and K-greater-than-proof-cost checkpoint/resume cases proving the root exemption logs the closing fact and the psm-v1 cross-field gate refuses a manifest whose non-open claim status lacks its durable root record, and claim-set consistency refusal `E-PSR-CONTRADICTION` including closure-implied impossibles like {WIN_X, WIN_O}; **manifest recovery tests** — corrupt-new/valid-old selection (CURRENT pointing at a corrupt or schema-refused manifest falls back to the highest-epoch valid predecessor), missing-CURRENT scan, and the uninitialized first-checkpoint case;
