## Purpose

One coherent theory package that (a) locks the engine math via a claim-numbered findings doc, (b) validates the backup operator for exactly this variant via two independently implemented value algorithms over one shared transition kernel, checked against a spec-derived golden transition suite, and (c) publishes the rules-fixture contract all pairs consume.

## 1. Findings doc — `theory/FINDINGS.md`

Claim-numbered; every claim carries a status from {cited, proven-here, computationally-verified, defined, proposed-for-ratification} plus its proof, citation, or generating computation, and names the fixtures that pin it.
The engine math lock consumes claims C1–C9 and C11 plus the proposals P1–P3; C10 is the engine root-bidding contract.
P1–P3 are proposals: the operator ratifies them at the math lock (orchestrator amendment 20260825-073330 for P1/P2; the second IMPL hold for P3; the human decision is exercised there, not here).

- C1 — Backup formula `T = b/(1 − a + b)` for `a ≤ b`.
  Cited for token games (Avni–Henzinger updated survey, MFCS 2022, Theorem 4; existence/uniqueness Avni–Henzinger–Ibsen-Jensen, WINE 2018, arXiv:1804.04372; original Lazarus–Loeb–Propp–Stromquist–Ullman `avg_P(x,y) = y/(1−x+y)`).
  The partisan extension (X-children ≠ O-children, winner places own mark) is proven here by induction on the finite DAG.
- C2 — Critical bid `r = (b − a)/(1 − a + b)` of combined budget.
  Proven here (no published closed form); pattern cite: Richman optimal bid, Lazarus et al. 1996 §3.
  Both post-payment identities stated and checked exhaustively in rationals (adopts the implementer-audit 968-case identity check as a regression test).
  In the zugzwang branch (`a > b`) the critical bid is defined as 0 — both players bid zero and the reported bid field carries `"0/1"`.
- C3 — Zugzwang branch: `a > b` ⇒ both bid 0, tie owner `h` forced to move; `T = a` when `h = X`, `T = b` when `h = O`.
  Proven here (one-step matrix argument + induction); no published counterpart exists for the alternation tie rule — Develin–Payne delegation, negative bids, and spendable-marker mechanisms are all rejected as category errors for cross-checking.
  Computational validation (per C11 no reachable Stage-1 state exercises this branch): the synthetic zugzwang harness — hand-constructed one-step games whose X-child and O-child are SYNTHETIC EXACT THRESHOLD-PAYOFF TERMINALS at assigned thresholds a = p_a/q_a and b with a > b (the child awards the X-win outcome iff `bx' * q_a > p_a * M'` exactly, in integers; these are deliberately synthetic payoff predicates, NOT canonical chip-comparison terminals, whose only threshold is 1/2 per C5, and no canonical rule is reinterpreted) — where exact discrete pure maximin/minimax at several scales and both tie owners must match the branch prediction (X forces the win iff the budget point clears `T = a` for `h = X`, `T = b` for `h = O`, outside the one-step granularity band), and both-zero bidding must be optimal.
  The harness validates the branch ALGEBRA only; it is not reachability evidence and not rules-kernel evidence (MR18).
- C11 — No reachable zugzwang in 3×3 auction TTT.
  Computationally verified: the exhaustive continuous census over all 22,186 (board, h) nodes finds zero `a > b` states; `a = b` (zero critical bid) is attained.
  Explanatory lemma (attempt-and-record, like C8a): extra-own-mark monotonicity — adding a player's own mark never raises that player's threshold, hence `a ≤ b` at every reachable state; recorded as discharged or undischarged with the obstruction.
  The census is pinned as a regression test; consequence: the C3 branch is engine-relevant only for UTTT (routing can plausibly produce reluctant-mover states), and Stage-1 validates it synthetically (P3).
- C4 — Tie-owner transition: `h' = opponent(actual mover)`; `h` toggles only when the tie owner moves (spec amended tie-state paragraph, main@2aef375).
  A blind per-ply toggle is wrong (reconciled implementer finding F5); fixtures pin h-persistence under consecutive paid wins by the same player.
- C5 — Chip-leader terminal: all-boards-closed no-macro-winner terminal has `T = 1/2` (chip comparison; exact equality ½–½).
  Proven here via the local one-step lemmas (C1–C3 branch analysis with the ternary terminal payoff) plus induction on the finite acyclic state DAG; the discrete convergence evidence (C8) corroborates but does not constitute the proof.
  Fixed-point non-uniqueness (charging-paper precedent) is sidestepped structurally: values are computed by backward induction on the DAG, never by fixed-point iteration.
- C6 — Root case `T(s, null)` (operator ruling R1; grill decision D2).
  Ordinary recursion in both oracles is over `h ∈ {X, O}` only; `null` exists solely at the root and is handled as two conditional solves.
  Deliverable: `T_lo(s) = min(T(s,X), T(s,O))` and `T_hi(s) = max(...)`, stated as robust conditional bounds — for `p > T_hi` X forces a win whichever branch the coin would take; for `p < T_lo` O forces a win; inside the envelope the findings doc states only what the two conditional games establish (which player the coin branch favors, and the conditional outcomes per branch).
  No claim is made about the value of the hidden-coin simultaneous game inside the envelope; an exact hidden-coin root value is the probabilistic solver grill decision D2 rejected, and reintroducing it would be a fresh operator decision.
  Root fixtures carry both realized coin branches.
- C7 — Monotonicity lemma (engine cutoff math consumes this).
  `F(a,b) = b/(1−a+b)` is nondecreasing in both `a` and `b` on [0,1]²; the zugzwang branch (`T = a` or `T = b`) is likewise monotone in child values; therefore the full backup operator is monotone, and interval/bound propagation in the engine is sound.
- C8 — Bounded discrete-vs-continuous claim, with the band defined a priori (details in section 2, `crosscheck.py`).
  Claim as provable by the sweep: at every tested scale, for every reachable state whose exact budget point lies strictly outside the a priori granularity band around the continuous threshold, the discrete outcome equals the continuous classification.
  No unqualified all-scales statement is made unless a separate theorem proves it; the band width, distance metric, scale semantics, convergence statistic, and pass threshold are all fixed before implementation (MR3) and are restated under `crosscheck.py`.
- C9 — Pure-strategy determinacy of the discrete game (load-bearing; hard math-lock blocker).
  Scope: deterministic `h ∈ {X, O}` states; the player action is the pair `(bid, intended move)`, and terminal utility for X is the ordered ternary `O-win = 0 < draw = 1 < X-win = 2`.
  Claim: pure-action maximin equals pure-action minimax at every reachable discrete state.
  C9a (reduction lemma, proven here): conditional on winning the auction at a given bid, the winner's best move is independent of the loser's bid and intended move — the post-win child depends only on (winner, winner's bid, winner's move); hence the full action matrix reduces to a bid-only matrix in which each cell's outcome uses the auction winner's optimal move.
  The oracle evaluates the bid-only reduced matrices; the lemma itself is additionally validated computationally on sampled states by comparing against the full `(bid, move)` action matrix.
  A single equality failure is a hard escalation that blocks the math lock, because the engine's deterministic threshold model would be wrong.
- C10 — Root bid-matrix contract for the engine.
  Regret matching must return the averaged strategy and report exploitability/average regret (Zinkevich et al. 2007, Theorem 2: ε-regret both sides ⇒ averaged profile is a 2ε-equilibrium; Hart–Mas-Colell for regret matching itself).
  Theory's LP reference (below) is the deterministic ground truth the engine validates against.

### Proposals P1–P3 (theory-owned; operator ratifies at the math lock)

R4 selected numeric types only; it did not settle knife-edge semantics (orchestrator amendment).
Both proposals are drafted a priori, and Stage-1 evidence calibrates them — the band is not defined after observing disagreements.

- P1 — Classification at exactly representable `p = T` (nonterminal): three distinct claims, never conflated (MR8).
  (i) Exact rules: referee integer arithmetic makes every realized canonical-scale game outcome unambiguous — this classifies played games, not optimal play.
  (ii) Exact optimal classification: the exact discrete oracle classifies optimal play only at the scales and states it actually solves (exhaustive N ≤ 32; spot 64/128).
  (iii) Canonical-scale (10^9-unit) optimal classification inside the band is unavailable from this package; no continuous-side equality convention is needed or asserted, and any future exact canonical classifier would be a new, separately authorized artifact.
- P2 — 10^9-unit approximation-tolerance contract for the engine: the risk-policy branch (MR9), with a named upgrade path.
  Contract: the engine may treat the continuous classification as trustworthy at a state s with current total budget M and continuous threshold T exactly when the integer distance `|bx − T·M|` exceeds `w(s) = E(s)` units, where `E(s)` is the number of empty cells remaining (`E(s) ≤ 81`; at 10^9 units the band is ≤ 8.1×10⁻⁸ of the combined budget).
  `w(s) = E(s)` is a proposed empirical safety envelope, not a proven error bound: no exact canonical-scale classifier exists inside it, so inside the band the engine must return interval/estimate value-quality metadata (consistent with C7 interval propagation and the engine's value-quality contract), never a forced winner, and handle root bidding through the bid-matrix path.
  C8a (upgrade proof obligation): a discrete-sufficiency-margin theorem — by induction on the DAG, a player whose integer budget exceeds `T·M` by more than the number of remaining auctions can force the continuous-side outcome with integer bids (round-up costs ≤ 1 unit per won auction; C7 monotonicity preserves the invariant).
  If the findings doc discharges C8a, P2's envelope is theorem-backed at every scale including canonical, and the extrapolation risk below vanishes; if C8a is not discharged, the operator ratification ask must explicitly name that canonical in-band optimal classification is unavailable and that ratifying P2 accepts the 3×3-to-UTTT extrapolation of the empirical envelope plus residual misclassification risk.
  Stage-1's sweep calibrates the envelope (tighten-only; never loosened silently) and reports the MR10 statistics.
- P3 — Zugzwang-branch validation basis (new at revision 5).
  Proposal: the operator accepts, at the math lock, that the C3 zugzwang branch is validated by proof (one-step matrix + induction) plus the synthetic harness only, because no reachable Stage-1 state exercises it (C11) — while UTTT routing may make it reachable in the engine's real game.
  The ratification ask must name this explicitly: the branch the spec flagged as the math-lock risk has no reachable-state witness in Stage-1, and accepting P3 accepts that residual gap for the UTTT engine.

## 2. Stage-1 two-oracle architecture — `theory/` (Python)

Layout: uv-managed project (`theory/pyproject.toml`), package `theory/auction_ttt/`, tests `theory/tests/`, CLI `python -m auction_ttt {solve,sweep,crosscheck,fixtures,kalai}`.
Python ≥ 3.12 supported (both audited interpreters); pinned dependencies: numpy, scipy, pytest (MR7); exact arithmetic per R4 — `fractions.Fraction` in the continuous oracle, machine integers in the discrete oracle, doubles only inside the LP solve with an exact certificate.

Independence statement (MR5): the two oracles are independently implemented value algorithms sharing one transition kernel (`rules.py`).
The kernel is validated against a spec-derived golden transition suite whose expected outcomes are hand-authored from the spec text and never generated through `rules.py`, covering at minimum: tie-owner persistence under consecutive paid wins, paid tie resolution (winner pays tied amount, loser pays nothing, loser's move ignored), both-zero alternation chains with routing, terminal-payment ordering (payment applies before the chip comparison), one-stack-zero auctions, and both root coin branches.
Property tests whose expectations come from the kernel are corroboration, not independence evidence; the golden suite is the independence evidence for the kernel.

- `rules.py` — shared transition kernel: 3×3 auction-TTT state (board 9 cells; tie owner `h ∈ {X, O}` for all non-root states; integer budgets held separately), legal moves, win/full detection, auction resolution per R1–R3.
  The root's hidden coin is not a kernel state: root analysis is two conditional solves (C6).
- `continuous.py` — exact-rational threshold DP: memoized backward induction over `(board, h)`; outputs `T`, critical bid `r` (defined as 0 in the zugzwang branch), both conditional best moves (if-X-wins / if-O-wins), and child tie owner per state.
  Canonical game is unrestricted first move (grill decision D1); the center-forced root value is reported as a named variant by filtering root moves.
  Asserts DAG-ness (marks only accumulate) and that every state's value is forced by its children.
- `discrete.py` — exact integer-budget oracle: state `(board, h, bx, bo)` with `h ∈ {X, O}`, ternary value ordered `O-win = 0 < draw = 1 < X-win = 2` for X.
  Per state: build the bid-only reduced matrix over `(i, j) ∈ [0..bx] × [0..bo]` (C9a: each cell resolves the auction — higher bid wins; tie `i = j` won by `h` — and applies the winner's optimal move for that post-payment budget state), then compute pure maximin `max_i min_j` and pure minimax `min_j max_i`, numpy-vectorized over the budget grid; equality asserted per C9.
  C9a validation: on a documented sample of states (stratified over near-band, masked both-zero, and uniform masked cases — no zugzwang stratum exists, C11; the C3 branch is validated by the separate census regression and synthetic harness), rebuild the full `(bid, move)` action matrix and confirm identical maximin/minimax values.
  Sweep scope (grill decision D3, restated at revision 5 per C11): exhaustive over all reachable states for every starting-chips-per-side N ≤ 32; targeted knife-edge/in-band spot checks at N = 64 and N = 128 (the formerly requested reachable-zugzwang spot subset is proven empty by C11; synthetic validation is separate).
  Runtime mitigations in order: numpy vectorization, monotonicity pruning (C7); if N = 32 is still intractable, dropping to N = 24 requires orchestrator sign-off.
- `crosscheck.py` — the C8 band check, all parameters fixed a priori (MR3):
  - Scale semantics: `scale = N` means initial chips per side; the game starts at `(bx, bo) = (N, N)` and current total `M = bx + bo` shrinks as bids are destroyed; every reachable `(board, h, bx, bo)` is checked at its own `M`.
  - Distance metric: for continuous threshold `T = p/q` (lowest terms) at state `(board, h)`, the integer distance of budget point `(bx, bo)` is `d = |bx·q − p·M| / q` — i.e., `|bx − T·M|` evaluated exactly in rationals, expressed in integer units.
  - Band rule: the point is in-band iff `d ≤ w(s) = E(s)` (empty-cell count), the same a priori width P2 uses.
  - Pass criterion (the acceptance law): zero points with `d > w(s)` misclassified, at every tested scale (hard fail otherwise).
  - Descriptive statistics (MR10, diagnostics not acceptance laws): per scale, report `R_mis(N) = max over misclassified points of d/w(s)` (dimensionless; defined as 0 when no point is misclassified — the empty-set convention) together with the state attaining it, plus the maximum in-band `d/w(s)` and the in-band occupancy fraction.
  - Cross-scale behavior: `R_mis` and in-band occupancy are reported across {8, 16, 32} and at the 64/128 spots; a rise on doubling is an anomaly finding routed to the orchestrator, not an acceptance failure by itself.
  - Extrapolation: the 10^9-unit rule is exactly P2 (risk-policy envelope, C8a upgrade path); the sweep calibrates, never silently widens.
- `lp_reference.py` — zero-sum matrix-game reference for root bid matrices (MR7).
  Solve: scipy HiGHS double LP for both players.
  Exact certificate, all in `Fraction` on the exact payoff matrix: strategy normalization (Σ = 1) and non-negativity for both returned strategies; candidate value `v` from the exact on-support equalizer solve; on-support equalities hold exactly; every off-support inequality holds for both players (each column response to x yields ≥ v for X's guarantee, each row response to y yields ≤ v); resulting exploitability of the certified pair is exactly 0.
  Failure behavior: if the double LP's support is degenerate or the exact certificate fails, re-solve with jittered degeneracy handling once; on second failure, fall back to an exact-rational LP (Fraction-arithmetic simplex/vertex path on the small matrix); if that also fails, escalate to the orchestrator — no silent tolerance.
  Output: game value, optimal mixed strategies, certificate status.
- `richman.py` — continuous Richman mode (average backup `R = (a + b)/2`) only, as a two-assertion machinery self-check with an explicit draw-terminal convention parameter:
  (i) literature convention — a full-board draw is a win for Bob/O (draw terminal 1, matching Develin–Payne §6's reduced game, doi:10.37236/357): the empty-board value must equal the published `R(TTT) = 133/256`;
  (ii) symmetric convention — draw terminal 1/2: the empty-board value must equal exactly 1/2, which is forced by complement symmetry of the average backup (swapping X/O complements every terminal and the backup preserves complements; the empty board is swap-invariant) and is therefore a second, independent machinery check.
  The canonical Stage-1 auction chip-comparison semantics are untouched — Richman mode exists only as this self-check; dm0n3y/biddingTTT is a secondary reference (reference-only, no license, no code reuse).
  The Develin–Payne star-chip discrete mode is explicitly out of scope.
- `fixtures_gen.py` — emits the fixture files of section 3 from oracle outputs plus the hand-authored golden cases.
- Kalai reproduction target (~101.84 vs 100 opening threshold): best-effort `kalai` subcommand on the unrestricted game; agreement or discrepancy is documented either way, and our exact solver is authoritative on disagreement (E0 blog number).

## 3. Rules-fixture schema v1 — theory-owned shared contract

Location: `theory/fixtures/` with the normative schema doc `theory/fixtures/SCHEMA.md` and the machine-checkable JSON Schema artifact `theory/fixtures/schema-v1.json`; validation in tests refers to the JSON Schema artifact, not prose (MR6).
Versioned from day one: every file carries `"schema_version": 1`; any change bumps the version and routes through s1.orchestrator-planner.
Publish early: SCHEMA.md + schema-v1.json + a seed legality/routing fixture set precede oracle completion.
Publication-ordering gate (MR21): no implementation dispatch may authorize fixture publication until an addressed s1.orchestrator-planner ordering ruling answers the 211157 request — if it authorizes publication-first, the dispatch cites that ruling and records the pending engine/harness repair obligations honestly; if it orders repairs-first, publication waits for them; the no-ruling action is to HOLD the early publication slice (read-only review work is not blocked).
Semantic resolution of the byte shape is this DD's; operational compatibility with the landed consumers is not claimed until the ruling and repairs land.

Format: JSON files by category, shape `{"schema_version": 1, "game": "uttt" | "ttt3" | "backup", "fixtures": [...]}` — `game` is the schema discriminator; the `backup` branch is a pre-publication extension that does not reinterpret canonical UTTT/ttt3 rules (MR16).

Conventions (consumers take these verbatim):

- Cells and local boards indexed 0–8, row-major.
- UTTT board: array of 9 strings, each 9 chars of `X | O | .`; ttt3 board: one 9-char string.
- Move: `[local, cell]` for uttt; single cell int for ttt3.
- `forced`: integer 0–8, or `null` meaning free choice (MR6 resolution — aligned with the harness contract's integer-or-null wire convention, DD-harness-c1-20260825; this choice is the theory-owned canonical encoding, and the boundary acknowledgment routes through s1.orchestrator-planner).
- Tie owner `h`: `"X" | "O" | null`; null valid only at move 1 (R1).
- Budgets and bids: integer units (R3); no floats anywhere in fixtures.
- Exact rationals (thresholds, critical bids): strings `"p/q"`; zugzwang critical bid is `"0/1"`.
- Continuous and discrete expectations never share a key.

Normative per-fixture shape (full field-by-field types in SCHEMA.md/schema-v1.json):

- Truly common envelope (every fixture, all game kinds): `id` (stable string, unique per file), `game`, `consumed_by` (non-empty list from {engine, harness, ui, theory}), `notes` (optional).
- `consumed_by` is NORMATIVE for every consumer: a consumer test suite must skip fixtures whose `consumed_by` excludes it (ruled at revision 5; the landed harness loader currently executes all uttt fixtures and requires repair).
- Game-state payload (uttt and ttt3 kinds only): `state` (board, `forced`, `h`, `budgets: {x, o}`).
- Backup payload (`game: "backup"` only, MR16): `a`, `b`, `h`, `expected_T`, `expected_critical_bid` — the first two and last two as rational `"p/q"` strings, `h ∈ {"X","O"}`; NO board/forced/budgets state.
- Legality fixtures: `expected_legal_moves` — the complete enumeration.
- Closure/routing fixtures (canonical byte shape, ruled at revision 5 after the landed-consumer collision — theory-c1-impl-blocker-2): `move` ([local, cell]), `move_by` ("X" | "O", required on every move-bearing fixture), `expected_closures` (array of `{local: 0–8, result: "X" | "O" | "full"}`, ordered by `local`), `expected_forced` (0–8 or null, null = free choice), `expected_terminal` (null | "macro_win" | "all_closed"; null = nonterminal).
  The terminal KIND is canonical (a boolean projection is a consumer-side reduction); closure records carry who closed each board or fullness, preserving analysis information.
- Auction-trace fixtures: `steps: [{bids: {x, o}, intended: {x, o}, expected: {winner, paid, applied_move, next_h, next_forced, tie_resolution}}]` where `tie_resolution ∈ {null, "h", "coin:X", "coin:O"}` — the root coin is lazily consulted: `"coin:*"` appears only at a step whose bids tied at move 1, recording the realized branch (both branches appear as separate fixtures).
- Terminal fixtures: expected result `"X" | "O" | "draw"` plus the chip margin after the final payment (terminal-payment ordering pinned).
- Threshold fixtures (ttt3): `expected_T` per `h` (both `h` values for root states), `expected_critical_bid`, `expected_best_move: {if_X_wins, if_O_wins}`, `expected_child_h`, and `discrete_expectations: [{"scale": N, "bx": ..., "bo": ..., "result": ...}]`; the category retains `a < b` and `a = b` (zero critical bid) reachable states — `a > b` states do not exist in the canonical game (C11).
- Backup-operator fixtures (`"game": "backup"`, new kind at revision 5): abstract cases per the backup payload above, explicitly covering `a > b` with both tie owners (the C3 branch the canonical game cannot witness), `a = b`, and `a < b`.
  Consumer boundary (MR17): the intended consumer is the theory-gated SUCCESSOR engine-search design's backup-operator unit tests — the landed engine rules-core reader consumes only `game: "uttt"`.
  Publication therefore emits these cases with `consumed_by: ["theory"]` unless an addressed pre-publication routing/acknowledgment from s1.orchestrator-planner authorizes the `engine` tag; the addressed boundary relay is filed alongside this revision, and the no-consumer action is: publish as theory-only evidence and defer the engine tag until the successor engine-search design lands.

Fixture categories (union of both audit lists): legality (including every free-choice case enumerating all empty cells in all open boards); closure/routing (local win closes, full-draw closes, send-to-closed ⇒ free choice, self-closing send, forced-board propagation); auction-resolution traces (both first-move coin branches, tied-bid payment, h-persistence under consecutive paid wins, 0–0 chains, all-in creating both-zero, both-zero multi-ply alternation with routing, one-stack-zero); terminal (macro win outright including double-line, nine-closed chip comparison at margins +1/−1/0 units, terminal-detection ordering); thresholds (as above, knife-edge cases at several scales with separate continuous and discrete fields); backup-operator cases (`game: "backup"`, as above).

Negative protocol fixtures (winning reply lacks a move, illegal winning move, wrong-board move) are harness-owned post-protocol-lock; theory supplies canonical legality expectations on request (R2 fault semantics live in the referee, not the game theory).

## 6. Risks

- Non-determinacy discovered at some discrete state: hard escalation to the orchestrator; math lock blocks; the engine model would need reshaping (this is exactly why Stage-1 gates the lock).
- N = 32 runtime blowout: mitigation ladder in section 2; N = 24 fallback is orchestrator-gated.
- Shared transition kernel is a common-mode surface by design; the independence claim is scoped to the value algorithms (MR5), and the golden transition suite is the kernel's independent check.
