## Purpose

One coherent theory package that (a) locks the engine math via a claim-numbered findings doc, (b) validates the backup operator for exactly this variant via two independent exact oracles, and (c) publishes the rules-fixture contract all pairs consume.

## 1. Findings doc — `theory/FINDINGS.md`

Claim-numbered; every claim carries a status from {cited, proven-here, computationally-verified, defined} plus its proof, citation, or generating computation, and names the fixtures that pin it.
The engine math lock consumes claims C1–C9; C10 is the engine root-bidding contract.

- C1 — Backup formula `T = b/(1 − a + b)` for `a ≤ b`.
  Cited for token games (Avni–Henzinger updated survey, MFCS 2022, Theorem 4; existence/uniqueness Avni–Henzinger–Ibsen-Jensen, WINE 2018, arXiv:1804.04372; original Lazarus–Loeb–Propp–Stromquist–Ullman `avg_P(x,y) = y/(1−x+y)`).
  The partisan extension (X-children ≠ O-children, winner places own mark) is proven here by induction on the finite DAG.
- C2 — Critical bid `r = (b − a)/(1 − a + b)` of combined budget.
  Proven here (no published closed form); pattern cite: Richman optimal bid, Lazarus et al. 1996 §3.
  Both post-payment identities stated and checked exhaustively in rationals (adopts the implementer-audit 968-case identity check as a regression test).
- C3 — Zugzwang branch: `a > b` ⇒ both bid 0, tie owner `h` forced to move; `T = a` when `h = X`, `T = b` when `h = O`.
  Proven here (one-step matrix argument + induction); no published counterpart exists for the alternation tie rule — Develin–Payne delegation, negative bids, and spendable-marker mechanisms are all rejected as category errors for cross-checking.
  Computationally verified by Stage-1 exhaustive sweep.
- C4 — Tie-owner transition: `h' = opponent(actual mover)`; `h` toggles only when the tie owner moves.
  A blind per-ply toggle is wrong (reconciled implementer finding F5); fixtures pin h-persistence under consecutive paid wins by the same player.
- C5 — Chip-leader terminal: all-boards-closed no-macro-winner terminal has `T = 1/2` (chip comparison; exact equality ½–½).
  Defined by the rules; validity of the whole threshold theory under this budget-valued terminal is established by discrete convergence (C8/C9), not assumed from literature (explicitly not covered anywhere; charging-paper precedent for fixed-point non-uniqueness).
  Non-uniqueness is sidestepped structurally: values are computed by backward induction on the finite acyclic state DAG, never by fixed-point iteration.
- C6 — Root case `T(s, null)` (operator ruling R1; grill decision D2).
  Deliverable is two-sided: `T_lo(s) = min(T(s,X), T(s,O))` and `T_hi(s) = max(...)`.
  For `p > T_hi` X forces a win regardless of the coin; for `p < T_lo` O forces a win; inside the band the outcome is coin-dependent and the findings doc characterizes optimal play there (win-probability ½ at knife-edge optimal play).
  No probabilistic root solver is built.
- C7 — Monotonicity lemma (engine cutoff math consumes this).
  `F(a,b) = b/(1−a+b)` is nondecreasing in both `a` and `b` on [0,1]²; the zugzwang branch (`T = a` or `T = b`) is likewise monotone in child values; therefore the full backup operator is monotone, and interval/bound propagation in the engine is sound.
- C8 — Discrete-vs-continuous statement under R4.
  Continuous `T` classifies exact integer-budget play correctly outside a granularity band; the band's occupants are enumerated by the cross-check at each tested scale; convergence is reported as scale doubles.
  Knife-edge `p = T` exactly is engine-internal (R4): referee rules are already exact; the engine explores ±1–2 units at the root.
- C9 — Determinacy: at every reachable discrete state, maximin = minimax over the full integer bid matrix.
  Computationally verified (grill decision D3 scope); a single failure is a hard escalation that blocks the math lock, because the engine's deterministic threshold model would be wrong.
- C10 — Root bid-matrix contract for the engine.
  Regret matching must return the averaged strategy and report exploitability/average regret (Zinkevich et al. 2007, Theorem 2: ε-regret both sides ⇒ averaged profile is a 2ε-equilibrium; Hart–Mas-Colell for regret matching itself).
  Theory's LP reference (below) is the deterministic ground truth the engine validates against.

## 2. Stage-1 two-oracle architecture — `theory/` (Python)

Layout: uv-managed project (`theory/pyproject.toml`), package `theory/auction_ttt/`, tests `theory/tests/`, CLI `python -m auction_ttt {solve,sweep,crosscheck,fixtures,kalai}`.
Python ≥ 3.12 supported (both audited interpreters); numpy + pytest; exact arithmetic per R4 — `fractions.Fraction` in the continuous oracle, machine integers in the discrete oracle, doubles only inside the LP with exact verification.

- `rules.py` — shared 3×3 auction-TTT state: board (9 cells), tie owner `h ∈ {X, O, null}` (null at move 1 only), integer budgets held separately; legal moves, win/full detection, auction resolution per R1–R3; the single rules implementation both oracles import, so a rules bug cannot self-confirm across oracles — mitigated by fixture-pinned hand cases and property tests.
- `continuous.py` — exact-rational threshold DP: memoized backward induction over `(board, h)`; outputs `T`, critical bid `r`, both conditional best moves (if-X-wins / if-O-wins), and child tie owner per state.
  Canonical game is unrestricted first move (grill decision D1); the center-forced root value is reported as a named variant by filtering root moves.
  Asserts DAG-ness (marks only accumulate) and that every state's value is forced by its children (no fixed-point ambiguity possible).
- `discrete.py` — exact integer-budget oracle: state `(board, h, bx, bo)`, ternary value {X-win, draw, O-win} ordered L < D < W for X; per state, the full `(bx+1) × (bo+1)` bid matrix resolves via child lookups (auction winner pays own bid to bank, tie → `h` wins and moves); computes both maximin and minimax, numpy-vectorized over the budget grid; equality asserted per C9.
  Sweep scope (grill decision D3): exhaustive over all reachable states for every starting-chips-per-side N ≤ 32; targeted knife-edge and zugzwang spot checks at N = 64 and N = 128.
  Runtime mitigations in order: numpy vectorization, monotonicity pruning (C7); if N = 32 is still intractable, dropping to N = 24 requires orchestrator sign-off.
- `crosscheck.py` — per state and budget pair: discrete outcome must equal `sign(p − T)`'s prediction outside the granularity band; band occupants logged with exact values; zero out-of-band disagreements is an acceptance criterion; convergence metrics reported as N doubles.
- `lp_reference.py` — zero-sum matrix-game reference for root bid matrices: scipy HiGHS double LP, then exact-rational verification of the returned support (equalizer linear system re-solved in `Fraction`); outputs game value, optimal mixed strategies, and the exactness certificate.
- `richman.py` — continuous Richman mode (average backup) only, as a machinery self-check: must reproduce the published `R(TTT) = 133/256`; dm0n3y/biddingTTT is a secondary reference (reference-only, no license, no code reuse).
  The Develin–Payne star-chip discrete mode is explicitly out of scope.
- `fixtures_gen.py` — emits the fixture files of section 3 from oracle outputs plus hand-authored rule cases.
- Kalai reproduction target (~101.84 vs 100 opening threshold): best-effort `kalai` subcommand on the unrestricted game; agreement or discrepancy is documented either way, and our exact solver is authoritative on disagreement (E0 blog number).

## 3. Rules-fixture schema v1 — theory-owned shared contract

Location: `theory/fixtures/` with the normative schema doc `theory/fixtures/SCHEMA.md`.
Versioned from day one: every file carries `"schema_version": 1`; any change bumps the version and routes through s1.orchestrator-planner.
Publish early: SCHEMA.md plus a seed legality/routing fixture set precede oracle completion so the engine pair unblocks.

Format: JSON files by category (git-diffable, trivially parseable from Python, C++, and TypeScript), shape `{"schema_version": 1, "game": "uttt" | "ttt3", "fixtures": [...]}`.

Conventions (consumers take these verbatim):

- Cells and local boards indexed 0–8, row-major.
- UTTT board: array of 9 strings, each 9 chars of `X | O | .`; ttt3 board: one 9-char string.
- Move: `[local, cell]` for uttt; single cell int for ttt3.
- `forced`: 0–8 or `"any"`.
- Tie owner `h`: `"X" | "O" | null`; null valid only at move 1 (R1).
- Budgets and bids: integer units (R3); no floats anywhere in fixtures.
- Exact rationals (thresholds, critical bids): strings `"p/q"`.
- Continuous and discrete expectations never share a key: `expected_T`/`expected_critical_bid` (rational strings) vs `discrete_expectations: [{"scale": N, "bx": ..., "bo": ..., "result": "X" | "O" | "draw"}]`.

Fixture categories (union of both audit lists):

1. Legality: position → complete legal-move enumeration, including every free-choice case enumerating all empty cells in all open boards.
2. Closure/routing: local win closes, local full-draw closes, send-to-closed ⇒ free choice, self-closing send, forced-board propagation.
3. Auction-resolution traces: sequences of (bids, intended moves) → resolved trajectory; both first-move coin branches; tied-bid payment (winner pays tied amount, loser pays nothing, loser's move ignored); h-persistence under consecutive paid wins; 0–0 chains; all-in creating the both-zero state; both-zero multi-ply alternation with routing; one-stack-zero cases.
4. Terminal: macro win outright (including double-line), nine-closed chip comparison at margins +1 / −1 / 0 units, terminal-detection ordering.
5. Thresholds (ttt3): expected `T` per `h` (and the two-sided root pair for null), critical bid, conditional best moves, child h; zugzwang cases with both owners; knife-edge cases at several total-budget scales with separate continuous and discrete expected fields.

Negative protocol fixtures (winning reply lacks a move, illegal winning move, wrong-board move) are harness-owned post-protocol-lock; theory supplies canonical legality expectations on request (R2 fault semantics live in the referee, not the game theory).

## 4. Verification and acceptance

All theory-package evidence is E2 (pytest + oracle runs on this laptop).

- Rules: hand-case unit tests plus randomized property tests (legal-move invariants, budget conservation minus destroyed bids, h-transition C4).
- Continuous oracle: Richman mode reproduces 133/256 exactly; the 968-case backup identity check passes; named zugzwang cases ((3/4, 1/4), (2/3, 1/3), both owners) match C3.
- Discrete oracle: 100% determinacy at N ≤ 32 (C9); spot scales pass.
- Cross-check: zero out-of-band disagreements at every tested scale (C8).
- Fixtures: schema-validated; every category above populated; consumed-by list recorded per category (no fixture without a named consumer assertion).
- Acceptance for the domain: findings doc complete with all ten claims discharged, fixture schema v1 + seed set published, Stage-1 sweeps green, math-lock report relay filed with E2 evidence.

## 5. Out of scope

- Any engine/harness/ui code or fixtures beyond the schema contract.
- UTTT-scale threshold solving (Stage-1 is 3×3 only).
- Develin–Payne star-chip discrete-Richman mode.
- A probabilistic root solver beyond the C6 band analysis.
- Protocol fault/negative fixtures (harness-owned).
- Any rules reinterpretation; R1–R4 are fixed inputs.

## 6. Risks

- Non-determinacy discovered at some discrete state: hard escalation to the orchestrator; math lock blocks; the engine model would need reshaping (this is exactly why Stage-1 gates the lock).
- N = 32 runtime blowout: mitigation ladder in section 2; N = 24 fallback is orchestrator-gated.
- Shared `rules.py` between the two oracles is a common-mode risk: accepted deliberately (the true independence requirement is engine-vs-theory, different languages); mitigated by fixture-pinned hand cases authored from the spec text, not from code.
- Engine misreading the root band or knife-edge semantics: C6/C8 are written as consumer-facing statements with fixtures.
