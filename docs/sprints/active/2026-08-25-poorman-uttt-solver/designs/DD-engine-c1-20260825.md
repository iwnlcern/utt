## 2. Position representation (locked; evidence E2)

Decision: Layout A — per-player `std::array<uint16_t, 9>` cell masks, plus cached derived state.

```c++
struct Position {
  std::array<uint16_t, 9> x, o;     // bit c = cell c of local board b
  std::array<uint32_t, 9> tern;     // incremental ternary code per local board (index into LocalTable)
  uint16_t macro_x, macro_o;        // locals won per player
  uint16_t closed;                  // locals closed (won or full)
  int8_t   forced;                  // 0..8, or ANY = -1
  TieState tie;                     // X, O, or NULL_FIRST_MOVE (R1)
};
```

Semantics are value-copy immutable: search copies the parent and applies one move; there is no make/unmake.
`tie` is the deterministic tie owner, stored as the last mover's opponent-derivable state; `NULL_FIRST_MOVE` is valid only before the first mark (R1).
Budgets never enter Position; they live in a root-side `BudgetContext` (section 9).

Evidence (E2, microbenchmark, Homebrew clang 22.1.8 `-O3 -std=c++2c`, Apple M5 Pro, 2026-08-25):
Layout A (`array<uint16_t,9>`) and Layout B (`__uint128_t` per player) are indistinguishable — both `sizeof == 80` with the shared caches, random-playout cost 23–24 ns/ply including movegen + value copy + apply + table lookup (~42M plies/s single-thread), pure copy fully vectorized (≈0), free-choice movegen over 81 cells ≈ 26 ns.
Decision therefore falls to simplicity: A gives direct per-local indexing with no 128-bit shift/extract code, and the fixture/debug path reads naturally.
Benchmark source was throwaway design evidence at `/tmp/uttt_bench/bench.cpp`; methodology and numbers are recorded here, and the harness for re-measurement is trivial to reconstruct from this section.
The 30 s/move budget is confirmed non-binding for the rules core: even 10^8 node visits spend under 3 s of pure rules-core work, so search strength will be bounded by tree shape and cutoff math, not representation.

## 3. Local lookup table (locked)

One global table of 19,683 entries (3^9 local-board states), indexed by the incrementally maintained ternary code `tern[b]` (cell c contributes `{empty:0, X:1, O:2} * 3^c`).
Each entry packs into one `uint64_t` (total 157 KB, L2-resident):

- `status` (2 bits): open / X-won / O-won / full-draw.
- `empties` (9 bits): empty-cell mask.
- `win_x`, `win_o` (9 bits each): cells that complete a local three-in-a-row for that player now (immediate wins; doubles as the opponent's block mask).
- `fork_x`, `fork_o` (9 bits each): cells that create two-or-more simultaneous local threats for that player.

Rationale: the same lookup that closes boards feeds move ordering (macro wins, local wins, blocks, forks) without per-node recomputation; the dispatch names these semantic entries explicitly.
Cells of closed boards never change, so `tern[b]` of a closed board is frozen and its entry stays valid.

## 4. Moves, movegen, terminal detection (locked)

Move = `{uint8_t board, uint8_t cell}`; move lists are fixed `std::array<Move, 81>` with a count, no heap in the search path.
Movegen: if `forced != ANY` and that board is open, enumerate `empties` of that board; otherwise enumerate `empties` of every open board.
Apply-move updates, in order: cell mask, `tern[b]`, table lookup; on close: `closed`/`macro_*`; then mover macro-win check (win masks over `macro_*`); then all-closed check; then `forced` = target cell's board, remapped to ANY if that board is closed; then `tie` = opponent of mover.
Terminal kinds exposed: `none`, `macro_win(player)`, `all_closed`.
`all_closed` resolution (chip comparison, ½–½ on exact equality) happens OUTSIDE Position, in the layer that owns budgets; Position never answers "who won a chip-count draw".
The first move is forced into the center local board (`forced = 4` in the initial state) per canonical rule 5.

## 5. Zobrist keying (locked key inputs; entry semantics gated)

64-bit Zobrist over exactly the state that identifies a search node: 81 cells × 2 players (162 randoms), forced state (10 randoms: 0..8, ANY), tie state (3 randoms: X, O, NULL_FIRST_MOVE).
This matches the spec's budget-independence claim for `T(s, h)`; if theory's findings overturn budget independence, the key gains budget inputs and section 10 reopens — that is exactly why TT value semantics stay gated.
Collision policy (locked): play mode stores a 32-bit secondary verification tag per entry (different Zobrist fold); acceptance/fixture mode runs with full-key verification (the complete Position compared on probe) so oracle-equality tests can never be polluted by a silent collision.

## 6. Protocol adapter boundary (locked)

The adapter is a separate translation unit/library; the search core has zero JSON and zero I/O dependencies.
JSON handling uses a vendored, pinned single-header library, linked ONLY into the adapter (operator decision, 2026-08-25; candidates evaluated at PLAN; license check before vendoring).
Flow: read one JSONL line → strict parse → validate (schema version, board shape, coordinate ranges, budget ranges per R3, `last_mover` consistency, forced-board consistency) → canonicalize into Position + BudgetContext → engine → serialize `{bid, move}` → single line out, flushed.
stdout carries protocol lines only; all diagnostics go to stderr.
The engine is stateless per request, which satisfies R2's re-request semantics structurally; a re-requested auction is just another request.
Bit-identical replies on re-request are NOT promised (the time budget makes search depth wall-clock-dependent); R2 requires a legal reply, not a reproducible one.
Malformed input, out-of-range values, or EOF produce a diagnostic on stderr and (for malformed requests) no stdout line — faulting is the referee's judgment, not the engine's.
The schema itself is harness-owned and consumed as-is; any change need routes through s1.orchestrator-planner.

## 7. Test seam (locked)

- Fixture ingestion: a test-only reader consumes theory's fixture schema verbatim (theory publishes the schema section early; engine requests it via the orchestrator if absent when needed). Fixtures drive: legal-move sets, closure/forced/ANY routing, terminal outcomes, and (small cases) expected thresholds and critical bids.
- Property tests: movegen equals a naive 81-cell reference implementation on random positions; closed boards never accept marks; forced-routing including closed-board→ANY; `tern[b]` always equals recomputation from masks; macro/closed caches always equal recomputation.
- Perft-style move counts at fixed depths from named positions, pinned as regression values.
- Deterministic clock: search takes an injected clock interface; tests use a fake clock, so "27 s soft stop" logic is testable without wall time.
- Threshold-equality tests vs theory's Stage-1 oracle use the locked tolerance: |T_engine − T_exact| ≤ 1e-9 on T, i.e. ±1 fixed-point unit of the 10^9 combined-budget scale (operator decision, 2026-08-25), run in full-key TT verification mode (section 5).

## 9. Budget plumbing (locked seam, gated interior)

`BudgetContext { int64 own_units, opp_units }` lives beside — never inside — Position.
Search maps `(Position, tie) → T` (and analysis metadata); the root layer alone combines T with BudgetContext to produce the integer bid per R3/R4.
Unsigned/64-bit-safe arithmetic for sums and products of unit counts (max 2×10^9 fits int64 with wide headroom for products in __int128 where needed).

## 10. GATED — backup operator implementation (drafted, not locked)

Draft per spec: `a = min over X-marked children of T`, `b = max over O-marked children of T`; if `a ≤ b`, `T = b / (1 - a + b)` and critical bid fraction `r = (b - a) / (1 - a + b)`; if `a > b`, zugzwang: `T = a` if tie owner is X else `b`.
Every interior node therefore evaluates up to 2× the legal-move count of marked children (both audits, independently).
`T(s, NULL_FIRST_MOVE)` (root, move 1, 50/50 coin) is theory-owned (R1); the engine implements whatever theory's findings doc specifies for it.
Locks only on theory's findings doc confirming the operator and zugzwang handling for this variant's chip-leader-draw terminal.

## 11. GATED — cutoff and bound math (drafted, not locked; first-class deliverable)

Both c1 audits concluded bound propagation is CORE to useful pruning, not a later optimization; this section is a first-class deliverable of the search-math lock.
Draft direction: `F(a, b) = b / (1 - a + b)` is monotone nondecreasing in both arguments on [0,1]² (theory findings doc must state and prove the exact monotonicity claim); therefore a running lower bound on `a` (min over X children so far can only decrease) and a running upper bound on `b` give sound bounds on T, enabling: early stop of a child subtree once its interval cannot change the parent's decision, ordering-driven narrowing, and an alpha-beta-analog window in T-space.
Deliverables at lock time: the pruning rule statement, its soundness argument (citing theory's monotonicity), and the interaction with zugzwang branch selection.

## 12. GATED — TT entry contract (drafted, not locked)

Draft entry: 32-bit verify tag; value payload (double T, or [lo, hi] interval pair — decided with section 11); bound type {exact, lower, upper}; searched depth/horizon; completeness flag (full-width vs widened); both conditional best moves (best X-marked child, best O-marked child — the UI's if-X-wins / if-O-wins needs both); generation/age for replacement.
Replacement policy: bucketed (4-way), depth-and-age aware; sizing configurable, default chosen at PLAN after profiling.
Locks with sections 10–11 because value semantics depend on the cutoff math.

## 13. GATED — selective widening and value-quality metadata (drafted; metadata SHAPE locked)

Widening draft: at free-choice nodes, order by tactical masks (section 3) plus routing quality, search a schedule of top-k both-player candidates with guaranteed minimum coverage, and tag any node whose move set was not exhausted.
A widened node's value can never be reported as proven: quality degrades to `estimate` (or `bound` when the searched subset yields a sound one-sided bound).
Value-quality metadata shape (LOCKED, operator decision 2026-08-25, cross-domain contract consumed by harness log + ui):

- `quality`: one of `exact` | `bound` | `estimate`; `exact` only when full-width search reached terminal resolution.
- `lo`, `hi`: present when `quality = bound`.
- `depth`: completed-iteration search depth for the reported value.
- `complete`: whether the reported iteration finished before the clock.

The carrier (where these fields ride in the game log / analysis channel) is harness-owned; this section defines the engine-side semantics only, and the routing note goes to s1.orchestrator-planner with this design's completion report.
Iterative deepening publishes only the last fully completed iteration (implementer-audit recommendation, adopted).
